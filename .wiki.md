# Resumen del proyecto
TimeLedger es un sistema web operativo que valida y liquida los registros de entrada y salida, confirma la asistencia diaria mediante un flujo de aprobacion (gerente de departamento/HR/CEO) y calcula y exporta la nomina semanal, quincenal o mensual, incluyendo horas extra, dias festivos y compensaciones.

# Descripcion de los modulos
- Backend (FastAPI)
  - Asistencia/liquidacion, carga de registros de acceso y flujo de aprobacion (aprobacion, rechazo y transicion de estado)
  - Horas extra (acumulacion, conversion a vacaciones y compensacion de retardos) y liquidacion de cierre
  - Calculo de nomina (agregacion por periodo/ciclo y exportacion CSV)
  - Consulta y administracion de datos maestros (empleados, codigos de motivos de asistencia, etc.)
- Frontend (React + Vite)
  - Layout comun (AppShell): navegacion lateral, cambio de actor (empleado) y seleccion de idioma
  - Internacionalizacion (i18n): textos de interfaz basados en claves de traduccion ko/es y utilidades de formato
  - Paginas funcionales (asistencia/registros de acceso/aprobaciones/vacaciones/horas extra/nomina/configuracion):
    - AccessLogs: carga JSON de registros del dispositivo, liquidacion diaria automatica (`settle`) y consulta de registros originales
    - DailyAttendance: lista de asistencia con filtros por fecha/departamento, edicion e historial, compensacion de retardos y aprobacion del cierre diario
    - Approvals: seguimiento de documentos en tres etapas y gestion de aprobaciones/rechazos
    - LeaveManagement: solicitudes y saldos de vacaciones, solicitudes de trabajo en fin de semana y consulta de estados
    - OvertimeBank: acumulacion de horas extra y festivas (`earn`), conversion a vacaciones (`convert`) y consulta de movimientos/saldos
    - Payroll: seleccion del ciclo de nomina, ejecucion del calculo, detalle de ejecuciones y exportacion CSV
    - MasterSettings: administracion de parametros de empleados y codigos de motivos de asistencia (categoria/efecto/activo/eliminacion)

# Arbol de directorios
- app/
  - .mgx/
    - config.yaml: conjunto de configuracion de ejecucion/despliegue
  - backend/
    - alembic/: migraciones del esquema de la base de datos
    - core/: autenticacion, configuracion, base de datos y utilidades comunes
    - data_models/: plantillas y esquemas de datos del dominio
    - dependencies/: dependencias de FastAPI
    - models/: entidades ORM (asistencia, motivos, aprobaciones, nomina, vacaciones, horas extra, empleados, etc.)
    - routers/: routers REST (asistencia, aprobaciones, registros, configuracion, nomina, etc.)
    - services/: servicios del dominio (motor de asistencia, aprobaciones, nomina, liquidacion y carga de datos, etc.)
    - utils/: utilidades de registro
    - main.py / lambda_handler.py / requirements.* / README.md / start_app_v2.sh, entre otros
  - frontend/
    - src/
      - components/: componentes UI comunes como AppShell
      - contexts/: archivos relacionados con AuthContext
      - hooks/: hooks como useSession
      - lib/: llamadas API, tipos, formateadores y utilidades i18n
      - pages/: pantallas como Index/AccessLogs/DailyAttendance/Approvals/LeaveManagement/OvertimeBank/Payroll/MasterSettings
      - styles (cuando corresponda)
    - public/: recursos estaticos
    - vite.config.ts / tsconfig*.json / tailwind.config.ts / package.json, entre otros

# Inventario de archivos
- app/backend/main.py: configuracion del servidor FastAPI y registro de routers
- app/backend/core/auth.py: gestion de autenticacion
- app/backend/core/config.py: gestion de configuracion del entorno
- app/backend/core/database.py: conexion a la base de datos y creacion de sesiones
- app/backend/core/enums.py: enumeraciones comunes
- app/backend/models/*: modelos ORM de asistencia, empleados, aprobaciones, nomina, vacaciones, horas extra, etc.
- app/backend/routers/*: conjunto de endpoints REST
- app/backend/services/*: logica del dominio (motor de asistencia, flujo de aprobaciones, calculo de nomina, etc.)
- app/backend/lambda_handler.py: punto de entrada para ejecucion serverless
- app/frontend/src/components/AppShell.tsx: navegacion, cambio de actor, seleccion de idioma y layout comun
- app/frontend/src/hooks/useSession.tsx: carga de empleados y persistencia del actor seleccionado
- app/frontend/src/lib/api.ts: wrapper de llamadas API, tipos de entidades y formateadores
- app/frontend/src/lib/i18n.ts: diccionario ko/es, persistencia del idioma y utilidades translate/format y useI18n
- app/frontend/src/pages/Index.tsx: consulta/bootstrap del dashboard (carga de datos y liquidacion) y renderizado de graficas
- app/frontend/src/pages/AccessLogs.tsx: carga/liquidacion de registros y consulta de registros originales
- app/frontend/src/pages/DailyAttendance.tsx: liquidacion diaria, edicion/historial, compensacion de retardos y aprobacion de cierre
- app/frontend/src/pages/Approvals.tsx: lista de documentos, seguimiento de etapas y gestion de aprobaciones/rechazos
- app/frontend/src/pages/LeaveManagement.tsx: solicitudes de vacaciones/trabajo en fin de semana y consulta de saldos/estados
- app/frontend/src/pages/OvertimeBank.tsx: acumulacion/conversion de horas extra y consulta de saldos/movimientos
- app/frontend/src/pages/Payroll.tsx: calculo de nomina, detalle de ejecuciones y exportacion CSV
- app/frontend/src/pages/MasterSettings.tsx: configuracion de empleados y gestion de codigos de motivos de asistencia

# Tecnologias
- Backend: Python, FastAPI, SQLAlchemy, Alembic
- Frontend: React, TypeScript, Vite, TailwindCSS, shadcn/ui (componentes), Recharts, Sonner, lucide-react y react-router-dom
- Otros: migraciones de base de datos y API de carga/liquidacion de datos

# Uso
## Backend
- Instala las dependencias en `app/backend` y ejecuta el servidor backend.
- Verifica el funcionamiento en un entorno local/Docker mediante las migraciones de base de datos y el flujo de carga/liquidacion de datos de demostracion.

## Frontend
- Instala las dependencias en `app/frontend`.
- Valida el frontend y genera el bundle con `lint`/`build`; despues comprueba la ejecucion.
